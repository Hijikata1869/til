# やること

- workout_exerciseを全セット込みでフロントに返すエンドポイントの実装

# 学び

```ruby
  def safe_attributes
    exercise = self.exercise.safe_attributes
    workout_sets = self.workout_sets.ordered.map { |s| s.safe_attributes }
    { id: id, exercise: exercise, memo: memo, sets: workout_sets }
  end
```

自分で書いたこのコードの、`exercise = self.exercise.safe_attributes`やのselfは冗長であった。モデルの中でexerciseと書いた時に、rubyは２つの可能性を考える。１つはexerciseという名前のローカル変数があるか。もう１つはexerciseという名前のメソッドがあるか。

今回、自分でexerciseという名前のローカル変数を作成したため、そちらが優先されてしまい、belongs_toで作成されたexerciseメソッドを使用するにあたりselfをつけなければならなくなった。

もし、変数名をexercise_jsonとしていれば、exerciseの前のselfを省略して書くことができた。

なぜそれが可能かというと、モデルのインスタンスメソッドの中では暗黙的にselfが呼ばれるから。だから、self.exerciseと書かなくても、exerciseと書くだけでメソッドが呼ばれる。

つまり、メソッドの中の`self.workout_sets`も同じこと。

だから、こう書き直せる。

```ruby
  def safe_attributes
    exercise_json = exercise.safe_attributes
    workout_sets_json = workout_sets.ordered.map { |s| s.safe_attributes }
    { id: id, exercise: exercise_json, memo: memo, sets: workout_sets_json }
  end
```

さらに言えば、わざわざローカル変数を用意する必要もない。だから、最終的に

```ruby
  def safe_attributes
    workout_sets_json = workout_sets.ordered.map { |s| s.safe_attributes }
    { id: id, exercise: exercise.safe_attributes, memo: memo, sets: workout_sets_json }
  end
```

これでいい。
