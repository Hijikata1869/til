# やったこと
rails g authenticationで作成されたコードのコードリーディング。

# 疑問点・詰まったこと
1. AuthenticationモジュールにextendされているActiveSupport::Concernはモジュール？

2. includedやclass_methodsはメソッド？

3. 特異メソッドはクラスメソッドではないのか？
```ruby
module Greet
  def hello
    "hi"
  end
end

obj = Object.new
obj.extend(Greet)
obj.hello   # => "hi"
```
なぜこのコードが成立するのか？特異メソッドがクラスメソッドなら、インスタンスメソッドとしてhelloは使えないのでは？

4. allow_unauthenticated_access(**options)の**optionsってなんだ

# 解答・解消方法
1. モジュール

2. メソッド。ActiveSupport::Concernにdefで定義されているインスタンスメソッド。それをAuthenticationモジュールの中でextendしているから、クラスメソッドとして使えている。

3. 特異メソッド = クラスメソッドではない。
特異メソッドとは、そのオブジェクト1個にのみ属するメソッドという意味で、クラスメソッドという意味ではない。
だから
```ruby
module Greet
  def hello
    "hi"
  end
end

obj1 = Object.new
obj2 = Object.new
obj1.extend(Greet)
obj1.hello   # => "hi"
obj2.hello # => NoMethodError
```
レシーバがクラスだった場合、extendはクラスメソッドになる、ということ。

4. `**options` と書くと、呼び出し側が書いた key: value 形式のものがすべてハッシュとして options に入る。
```ruby
allow_unauthenticated_access only: :create
# → options == { only: :create }

allow_unauthenticated_access only: [:create, :index], raise: false
# → options == { only: [:create, :index], raise: false }

allow_unauthenticated_access
# → options == {}
```
だから今回の場合
```ruby
def allow_unauthenticated_access(**options)
  skip_before_action :require_authentication, **options
end
```
このoptionsで受け取った引数を、ただskip_before_actionに横流ししているに過ぎない。
何をキーとして受け取れるかの仕様はskip_before_actionの実装を見て判断する必要がある。
