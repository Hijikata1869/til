# やったこと

引き続きrails g authenticationで生成されたコードのコードリーディング。

# 決めたこと

- 自動生成されたコードにはビューの使用を前提にしたコードもあり、APIモードでは不要なものもある。ただ、設計を借りてくることはできると考える。
- Currentは使わない。コントローラー内で完結するので@current_sessionで足りる。
- sessionsテーブルはuser_id + timestampsのみ。ip_address/user_agentはいらない。
- セッション期限はcreated_at基準。last_activate_at入れない。
- rate_limit入れる。ログインは総当たり攻撃の標的なので。

2. 以下のコードに出てきたrate_limitってなに？

```ruby
class SessionsController < ApplicationController
  allow_unauthenticated_access only: %i[ new create ]
  rate_limit to: 10, within: 3.minutes, only: :create, with: -> { redirect_to new_session_path, alert: "Try again later." }

  def new
  end

  def create
    if user = User.authenticate_by(params.permit(:email_address, :password))
      start_new_session_for user
      redirect_to after_authentication_url
    else
      redirect_to new_session_path, alert: "Try another email address or password."
    end
  end

  def destroy
    terminate_session
    redirect_to new_session_path, status: :see_other
  end
end
```

# 解消方法

1. ActiveSupport::CurrentAttributesを継承したクラス。現在のリクエストの中でグローバル変数が使える。コントローラー内だけでなく、モデルで現在ログイン中のユーザーを取得したい、といった要件がある場合に使える。

2. Rails 8で追加された、アクションの呼び出し回数を制限する機能。

ログインは「正しいパスワードを探す試行」そのものが攻撃になるので、
他のエンドポイントと違って回数制限が要る。

- to: 上限回数
- within: 期間（3.minutes はActiveSupportがIntegerに生やしたメソッド）
- only: 対象アクション（before_actionと同じオプション。内部でbefore_actionを登録しているだけ）
- with: 上限超過時の処理。-> {} はラムダ（無名関数）で、即時実行されず後から呼ばれる

注意: カウントはRails.cacheに保存される。開発環境のデフォルトは:null_storeで
何も保存しないので、bin/rails dev:cache しないと動作確認できない。
